# Muse Daily Recorder v1.8.2 (S3 업로드 + 이벤트 마커 + 일일 요약)

[English](../README.md) | [中文](../README.zh-CN.md) | [日本語](README.ja.md) | 한국어 | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | [Português](README.pt.md) | [Русский](README.ru.md)

**음성 녹음기를 대체합니다.** 휴대폰은 항상 곁에 있고, 녹음은 자동으로 나뉘어 자신의 클라우드에 자동 백업되며, 이벤트 마커와 전사, 일일 요약을 통해 녹음을 검색할 수 있습니다. 케이블 전송도, 분실도 없습니다.

Muse 자체는 마이크를 계속 들을 수 없으므로, 이 구성은 세 부분으로 이루어집니다.

1. **Android 앱**(`MuseRecorder.apk`): 포그라운드 서비스로 녹음하며 **60분마다 자동으로 구간을 나눕니다**(.m4a, 구간당 약 21 MB). 끝난 구간은 자신의 **S3 호환 오브젝트 스토리지**로 자동 업로드됩니다. 실패한 업로드는 대기열에 남아 재시도되며, 앱의 **업로드 대기 목록**에서 확인할 수 있습니다.
2. **이벤트 마커**: 녹음 중 중요한 순간을 손쉽게 표시합니다(아래 참조). 마커는 오디오와 함께 버킷으로 전송됩니다.
3. **일일 요약**(Muse 측): `receiver/fetch_day_from_s3.py`가 전날의 녹음과 마커를 버킷에서 가져와 → 전사하고 → Muse가 일일 보고서로 정리합니다.

v1.2부터 앱은 **S3 전용**입니다(v1.0의 자체 수신 서버, v1.1의 Supabase 직접 업로드는 제거됨. 이전 수신 스크립트는 참고용으로 `receiver/`에 남아 있습니다).

## 1. S3 버킷 준비하기 (Cloudflare R2 예시)

1. cloudflare.com에 가입하고 R2를 활성화합니다(무료 등급: 10 GB, 다운로드 무료. 활성화 시 카드 등록을 요구할 수 있지만 무료 한도 내에서는 과금되지 않습니다). 버킷을 만듭니다(예: `recordings`).
2. "R2 API 토큰 관리"에서 **해당 버킷에만 읽기/쓰기 권한이 있는 토큰**을 만듭니다(Object Read & Write, 버킷 지정). Access Key ID, Secret Access Key, Account ID를 기록합니다(엔드포인트는 `https://<AccountID>.r2.cloudflarestorage.com`).
3. 앱에서 **Cloudflare R2** 프리셋을 선택하고, 엔드포인트의 `<AccountID>`를 실제 ID로 바꾼 뒤 버킷 이름과 두 개의 키를 입력하고 저장합니다.

다른 제공업체도 마찬가지입니다(모두 앱에 프리셋이 있습니다): Backblaze B2, Alibaba Cloud OSS(S3 호환 모드 + 계정 AccessKey 사용. 버킷은 콘솔에서 생성), Tencent Cloud COS(버킷 이름에 `-APPID` 접미사 필요. SecretId/SecretKey 사용), AWS S3, Qiniu Kodo, 또는 "사용자 지정"으로 모든 S3 호환 서비스. Alibaba/Tencent/AWS/Qiniu는 "가상 호스트 스타일"을 체크해야 하고, R2/B2는 체크하지 않습니다.

> 보안 참고: Secret Key는 휴대폰 앱 안에만 두세요. 채팅이나 공개된 곳에 절대 붙여넣지 마세요. 토큰을 단일 버킷으로 제한해 두면 만일 유출되더라도 피해를 줄일 수 있습니다.

## 2. 설치 및 일상 사용

1. `MuseRecorder.apk`를 휴대폰으로 보내 설치합니다(개인용 앱으로 스토어에 올라가 있지 않으므로 "알 수 없는 출처"를 한 번 허용합니다). 이전 버전 위에 설치하면 설정이 유지됩니다.
2. 앱을 열고 → "⚙️ 구성"을 눌러 S3 정보를 입력하고 저장합니다(저장하면 즉시 업로드가 실행됩니다) → "백그라운드 실행 허용(배터리 최적화 해제)"을 누릅니다 → 빨간 원형 버튼을 눌러 녹음을 시작합니다(녹음 중에는 사각형 버튼으로 바뀌고 아래에 실시간 파형과 현재 구간의 남은 분이 표시됩니다). 마이크/알림 권한을 허용하세요. Samsung 휴대폰에서는 앱 배터리를 "제한 없음"으로 설정하는 것이 좋습니다.
3. **업로드는 완전 자동입니다**: 대기 목록에 각 구간의 상태가 표시되고, 업로드 중에는 실시간 진행률이 나타나며, 완료 또는 실패 후에도 결과가 화면에 남습니다. 실패 시에는 서버의 오류 메시지가 함께 표시됩니다. 실패한 구간(예: 오프라인)은 대기열에 남아 자동으로 재시도됩니다. 수동 "지금 다시 업로드" 버튼은 설정을 변경한 뒤, 또는 자동 재시도가 30분 이상 실패한 뒤에만 나타납니다. S3 및 녹음 설정은 기본적으로 접혀 있으며, "⚙️ 구성"을 눌러 펼칩니다.
4. **언어**: 설정 상단의 언어 선택기에서 시스템 기본값 외에 영어, 중국어, 일본어, 한국어, 스페인어, 프랑스어, 독일어, 포르투갈어, 러시아어를 선택할 수 있으며 즉시 적용됩니다. 앱 이름은 모든 언어에서 항상 "Muse Daily Recorder"입니다.
5. 오른쪽 상단의 파란색 ⓘ 버튼을 누르면 내장 도움말 페이지가 열립니다(녹음, 업로드, 마커, 설정, FAQ, 개인정보).

## 3. 이벤트 마커 (일일 보고서용 "핵심 표시")

- **대화 스위치**: 중요한 대화가 시작되면 켜고, 끝나면 끕니다.
- **회의 스위치**: 회의 전에 켜고, 끝나면 끕니다.
- **📌 셀프 노트 버튼**: 떠오르는 생각, 아이디어, 할 일을 길게 눌러 기록합니다. 녹음 중에는 그 순간만 표시하고, 유휴 상태에서는 독립적인 음성 메모로 녹음됩니다.
- 마커는 날짜별로 버킷의 `markers/events-<날짜>.jsonl`에 저장됩니다. 일일 보고서는 마커를 기준으로 대화/회의를 나누고, 셀프 노트 근처의 내용에 특별히 주목합니다. 스위치 상태는 기억되므로 앱을 닫았다 다시 열어도 꼬이지 않습니다.

## 4. 일일 요약 (Muse 측)

```bash
# 환경 변수: S3_ENDPOINT / S3_BUCKET / S3_ACCESS_KEY / S3_SECRET_KEY / S3_REGION / S3_STYLE (path|virtual)
# 선택: S3_DELETE_AFTER=1 → 가져온 뒤 클라우드 원본을 삭제 (클라우드 공간 절약. 전사본과 보고서는 Muse 측에 남습니다)
python3 receiver/fetch_day_from_s3.py --date 2026-10-23
python3 receiver/summarize_day.py   --date 2026-10-23
```

전사는 두 가지 중 선택합니다: `OPENAI_API_KEY` 설정(Whisper API), 또는 Muse 컴퓨터에 `pip install faster-whisper`(로컬, 무료). 그런 뒤 Muse에게 보고서 시간(예: 매일 아침 7:30)을 알려주면 자동으로 실행해 채팅에 게시하는 예약 작업을 설정합니다.

## 5. 현실적인 주의사항

- **배터리**: 종일 녹음 시 시간당 약 3~6%를 사용합니다. 가능하면 밤에 충전하면서 녹음하세요. "Wi-Fi에서만 업로드" 옵션이 있습니다.
- **저장 공간**: 하루 약 500 MB. 로컬 복사본은 업로드 성공 후 기본적으로 삭제됩니다. 클라우드 측은 `S3_DELETE_AFTER=1`이나 최근 며칠만 유지하는 버킷 수명 주기 규칙을 권장합니다.
- **안정성**: Android는 백그라운드 녹음을 엄격히 제한합니다. 상태 표시줄의 상시 알림은 시스템 요구 사항이며, 녹음 중이라는 증거이기도 합니다. 아침저녁으로 앱의 "X분간 녹음 중"을 흘끗 확인하면 충분합니다.
- **준수 사항**: 타인과의 대화를 녹음하는 것은 많은 지역에서 상대방의 동의를 필요로 합니다. 합법적이고 상대방이 알고 있는 상황에서만 사용하세요.

## 6. 구성

- `app-project/`: 앱 전체 소스(Java + Android 프레임워크 API. S3 서명은 순수 Java 구현으로, AWS 공식 SigV4 테스트 벡터로 검증됨).
- `receiver/fetch_day_from_s3.py`: S3 버킷에서 오디오와 마커를 가져옵니다(Python 표준 라이브러리만 사용. 서명 구현도 동일한 공식 테스트 벡터를 통과).
- `receiver/summarize_day.py`: 전사 + 보고서 초안. `receiver/server.py`, `fetch_day_from_supabase.py`는 이전 방식의 아카이브입니다.
- `build-apk.sh`: Android SDK build-tools를 직접 사용해 APK를 빌드합니다.
- `.github/workflows/build.yml`: master에 푸시할 때마다 CI가 빌드하고 동일한 APK를 두 가지 릴리스로 게시합니다. 항상 최신 빌드를 가리키는 롤링 `latest` 릴리스와, 버전별로 영구 보관되는 정식 릴리스(태그 `vX.Y.Z`)입니다. 최신 빌드는 언제든 여기에서 다운로드할 수 있습니다: https://github.com/skyvense/muse-recorder/releases/tag/latest
- `muse-recorder.keystore` + `keystore-info.txt`: 서명 키 — **반드시 안전하게 보관하세요**. 업그레이드는 동일한 키로 서명해야 하며, 그렇지 않으면 이전 버전 위에 설치할 수 없습니다. 암호화된 복사본은 `vault/`에 있습니다(AES-256-CBC + PBKDF2).
